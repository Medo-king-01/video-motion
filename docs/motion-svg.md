# SVG مستقر ضمن عقد محدود للرندر

هذا مسار **مستقر ومحدود** لملفات المسارات الثابتة، وليس رندرًا كاملًا لكل مواصفات SVG. لم نُدخل متصفحًا أو SVG runtime في P، ولا نحمّل ملفات خارجية وقت الرندر. يحوّل `tools/svg_compile.py` الملف محليًا إلى JSON هندسي موحد قبل رندر P/K/R. أي عنصر/خاصية غير مدعومة تُرفض بدل إهمالها بصمت. راجع الرخصة والمصدر قبل استخدام أي ملف.

## الاستخدام

```bash
export PATH="$PWD/.venv/bin:$PWD/tools/bin:$PATH"
python3 tools/svg_compile.py asset.svg plan/asset-svg.json --steps 32
```

يجب أن يكون ملف الخرج جديدًا. اقرأ JSON في مرحلة تهيئة المشهد، وليس داخل كل إطار. في K:

```js
import {drawSvgArt} from '../lib/svg-canvas.js';
// plan من ملف JSON المحلي الذي جرى تجميعه قبل الرندر
// progress اختياري، من 0 إلى 1؛ للتوقيت استخدم الزمن المحلي الصريح.
drawSvgArt(ctx, plan, {x:120,y:400,width:500,height:500,progress:0.7});
```

في R استخدم `<SvgArt plan={plan} x={120} y={400} width={500} height={500} progress={progress}/>` مع نوع `SvgPlan`. في P: `from svg_art import draw_svg_art` ثم `draw_svg_art(image, plan, {'x':120,'y':400,'width':500,'height':500,'progress':0.7})`. الأحجام الرقمية بالبكسل؛ يصغر/يكبر viewBox بنسبة موحدة مع توسيط، دون قص عند حد الصندوق. تأكد من الكادر وsafe zones بنفسك. `progress` يقتطع **كل contour مستقلًا** حسب طولها؛ التعبئة ثابتة ولا تُمسح مع stroke.


## نوافذ خط مستقلة ومؤلَّفة

إضافة المرحلة العاشرة تعمل على الخطة نفسها، دون تغيير المسارات أو التعبئة:

```js
// أرقام تقدم مشتقة من الزمن المحلي للمشهد، مثال زخرفي لا مرساة VO.
drawSvgArt(ctx, plan, {
  x:120, y:400, width:500, height:500,
  strokeStart:0.2, progress:0.8, strokeOffset:0,
  strokeWindows: {'svg-0': [null, {start:0, end:0.5, offset:0}]},
});
```

- `progress` هو نهاية النافذة العامة، كما في النسخة القديمة، و`strokeStart` بدايتها (الافتراضي 0)،
  و`strokeOffset` إزاحة كسرية موقعة (الافتراضي 0). يجب أن يكون `0 ≤ start ≤ end ≤ 1`، والإزاحة
  finite لا يتجاوز قدرها المطلق 1,000,000. النسبة محسوبة من طول polyline **كل contour** بعد التقريب.
- `strokeWindows` اختياري؛ مفاتيحه IDs **الخطة الناتجة** مثل `svg-0` افتراضيًا.
  انظر JSON المجمع؛ هذه الأرقام تتبع ترتيب الأشكال وقد تتغير إذا تغير المصدر. بديلًا، مرر
  `--preserve-ids` إلى compiler للمحافظة على ID صريح آمن وفريد لكل شكل؛ يرفض ID ناقصًا
  أو مكررًا أو غير آمن أو يطابق ID تدرّج، ولا يغيّر ترتيب الرسم أو يطابق المعنى تلقائيًا. لكل مفتاح مصفوفة
  بطول عدد contours لهذا الشكل. `null` يستخدم النافذة العامة، أو استعمل `{start,end,offset?}`؛
  عند حذف offset الخاص يُستخدم `strokeOffset`. ID مجهول، عدد خاطئ، حقل إضافي أو قيمة غير صالحة
  يفشل قبل الرسم بدل تجاهله. لا تتغير التعبئة، حتى عندما لا يوجد stroke ظاهر.
- الإزاحة تلتف modulo 1 في المسارات المغلقة **والمفتوحة**؛ في المفتوح قد ينتج مقطعان منفصلان بنهايات
  مستديرة. نافذة طولها صفر لا ترسم خطًا، وطولها واحد يرسم المسار كاملًا بغض النظر عن offset.
  هذا trim هندسي محدود وليس محاكاة `stroke-dasharray` أو markers أو حفظ أسلوب SVG العام.
- في R، مرر `strokeStart`, `strokeOffset`, `strokeWindows` بالأنواع نفسها إلى `<SvgArt />`؛
  وفي P ضع المفاتيح نفسها داخل dict خيارات `draw_svg_art`. إذا حُذفت الخيارات الجديدة يبقى
  `progress` وحده كما كان. القيم تُحسب صراحةً لكل إطار، ويمكن وضع حدود منفصلة في وضع reduced
  المؤلَّف دون تغيير النصوص أو بوابات الحقائق أو مدة المشهد.
- لا تربط ظهور المعلومة تلقائيًا بهذا الرسم؛ بوابة الـVO المقاس ومساحات الأمان والمراجعة البصرية
  مسؤولية خطة المشهد. اختبارات P/K/R تفحص مناطق خط داخلية وK replay، لا تطابقًا تامًا للحواف بين المحركات.


## تدرّجات محلية ثابتة محدودة

يدعم compiler تدرّج تعبئة خطيًا أو دائريًا عبر تعريفات محلية فقط، ثم يحولها إلى بيانات رقمية
وtokens قبل الرندر؛ لا يحتفظ بـURL خارجي أو XML. مثال:

```xml
<svg viewBox="0 0 100 100">
  <defs>
    <linearGradient id="tone" gradientUnits="userSpaceOnUse" x1="0" y1="0" x2="100" y2="0">
      <stop offset="0" stop-color="#CB271B"/>
      <stop offset="1" stop-color="#0A0A0A"/>
    </linearGradient>
  </defs>
  <rect x="0" y="0" width="100" height="100" fill="url(#tone)" fill-rule="evenodd"/>
</svg>
```

يمكن بدلًا من ذلك `<radialGradient id="tone" gradientUnits="userSpaceOnUse" cx="50" cy="50" r="50">`؛
المركز هو نقطة البداية ونصف القطر موجب. الشروط المقصودة:

- `<defs>` واحد مباشر تحت الجذر، حتى 16 تعريفًا؛ لكل تعريف ID محلي فريد، وإحداثيات عددية صريحة
  بوحدات المستخدم، و2–16 stops مرتبة strictly من 0 إلى 1، بألوان hex مطابقة للـpalette فقط.
  التدرج بين هذه الألوان ينتج ألوانًا وسيطة؛ تحقق من الهوية والتباين. أسلوب `medo-motion/styles/showreel.md` يمنع التدرجات أصلًا؛ هذه القدرة الاختيارية لا تتجاوز دليل الأسلوب.
- المرجع `url(#id)` مسموح **للتعبئة فقط**، حتى في inline style؛ لا URL خارجي أو stroke gradient.
  لا `objectBoundingBox`، نسب مئوية، stop opacity، focal point مختلف، spreadMethod، وراثة gradients،
  أو `gradientTransform`. يسمح للشكل/المجموعة بالترجمة والدوران والانعكاس والمقياس الموحد المتعامد فقط؛ المقياس غير الموحد أو shear يُرفضان بدل تغيير النتيجة بصمت.
- opacity على الشكل يطبق بعد تجميع التعبئة والحد، بما فيها التدرجات؛ في K يستعمل buffer مؤقتًا
  عند opacity جزئي، ويتطلب K وضع source-over بلا Canvas filter أو shadow؛ وفي P/K لا يتجاوز
  سطح الصورة 4,194,304 بكسل لهذه الحالة. لا يرث opacity من مجموعة.
- المسار والحلقات والثقوب يخضعون لنفس even-odd والحدود. P يحسب sRGB على مراكز البكسلات ويفرض
  حد 4,194,304 بكسل على صندوق قناع كل شكل متدرج؛ K Canvas وR SVG يستخدمان التدرج الأصلي.
  النتائج قد تختلف عند الحواف أو بدرجات تقريب اللون، وليست إثبات تطابق بكسلات بين المحركات.
- morph للحلقات المتوافقة يقبل تدرّجًا **ثابتًا متطابقًا** في الطرفين فقط؛ لا يمزج ألوانه أو إحداثياته.
  crossfade موجود للأصول المختلفة، وهو تلاشي لا morph هندسي. راجع الأداء عند استخدام مساحات كبيرة.

## تصريحات style مضمّنة محدودة

يقبل compiler الآن `style` محليًا على `<svg>` أو `<g>` أو الأشكال، **فقط** للخصائص
`fill`, `stroke`, `stroke-width`, `fill-rule` و`opacity` على الأشكال (قيمة رقمية من 0 إلى 1).
الخاصية المضمّنة تتقدم على attribute المقابل، وتورث خصائص الطلاء للمجموعات/الأبناء.
مثال: `<g style="fill:#CB271B;fill-rule:evenodd;stroke:#0A0A0A;stroke-width:2">`.
يُرفض التكرار وCSS variables و`!important` والتعليقات وأي خاصية أو طلاء أو وحدة غير مدعومة؛
لا يحلل stylesheets أو selectors أو cascade العام. `opacity` على المجموعات مرفوض حتى لو 1؛ يُسمح به على الشكل فقط.
هذا تحويل قبل الرندر، وليس تنفيذ CSS وقت الرندر، ولا يغيّر شروط palette والموارد الخارجية.

## المقبول والمرفوض

- `<svg viewBox="x y width height">` صريح، و`<g>` متداخلة، و`<path>` و`rect/circle/ellipse/line/polyline/polygon` الثابتة. مسارات M/L/H/V/C/S/Q/T/A/Z، صغيرة/كبيرة ومطلقة/نسبية وتكرار المعاملات، بما فيها arc flags المتجاورة، تتحول إلى polylines متعددة ومحدودة. تقريبات منحنيات ثابتة بـ4–64 خطوة لكل مقطع (`--steps`، الافتراضي 32)، **ليست حد خطأ هندسي مضمونًا**؛ راجع بصريًا وارفَع الخطوات عند الحاجة ضمن سقف النقاط.
- يجب التصريح بـ`fill` لكل path أو المجموعة الموروثة: `none` أو hex مطابق تمامًا لهوية ميدو مثل `#CB271B`، أو مرجع gradient محلي محدود كما أدناه. لا تُقبل أسماء الألوان مثل `red` حتى لا يختلط أحمر SVG القياسي بلون الهوية المختلف. `stroke` كذلك و`stroke-width` رقم غير سالب. يجب تحديد `fill-rule="evenodd"` للتعبئة؛ عدة contours/ثقوب تعمل بـeven-odd. opacity الشكل 0–1 ويُطبق على المجموعة الناتجة من fill وstroke معًا. يُرسم stroke بنهايات وزوايا مستديرة؛ هذا أسلوب adapter واضح وليس الحفاظ على كل إعدادات stroke في المصدر.
- يدعم compiler تحويلات `matrix/translate/scale/rotate/skew` الثابتة (بما فيها المتداخلة)، ويطبقها على النقاط. الأشكال ذات gradient المستورد تتطلب transform موحدًا ومتعامدًا كما هو موضح أدناه. عند وجود stroke مرئي يجب أن يكون التحويل المحصل مقياسًا موحدًا مع دوران/انعكاس، وإلا يُرفض بدل تشويه الخط. يُقبل `style` مضمّن محدود كما أدناه، لكن لا stylesheets أو CSS عام أو filters أو masks أو clipPaths أو `<use>` أو text أو صور أو animations أو scripts أو شبكات أو DTD/entities. لا `nonzero` للتعبئة، ولا وحدات `px`/`%` للأبعاد؛ تُرفض هذه مدخلات صراحة. يُقبل XML declaration والتعليقات العادية، لكن DTD/entities وباقي processing instructions مرفوضة قبل التحليل. حوّل الأصول خارجيًا إلى مسارات ثابتة ومسطّحة ذات even-odd مع palette صريحة، ثم افحصها. لا تستخدم compiler كـsanitizer عام لتقديم ملفات XML خام للمتصفح.
- الوثيقة تقبل 256KB، 128 path، 64 contour لكل path، 1024 أمرًا لكل path، 4096 نقطة لكل contour و65536 نقطة إجمالية. إحداثيات وأبعاد ومدى المقياس مقيدة؛ المدخلات الخارجة تفشل. تحقق adapters أيضًا بنية JSON والـpalette قبل الرسم؛ لا يُنفذون markup.
- يوجد [morph محدود للحلقات المتعددة المتوافقة](motion-nested-morph.md) يطابق الترتيب المؤلَّف ويفحص الانتقال تحفظيًا؛ اختلاف topology أو المطابقة التلقائية أو morph SVG العام لا تزال غير منفَّذة. يمكن كذلك استخدام `compileMorph` على حلقة واحدة. لا مساواة pixel-perfect بين Pillow وCanvas وSVG DOM، خاصة الحواف والـstroke.

الاعتمادية التي تقوم بفك path هي `svgpathtools==1.7.2` (MIT) و`svgwrite==1.4.3` تبعية لها (MIT)، مقيدتان في `tools/constraints.txt` وتُثبتان مع `tools/setup.sh`. لا خدمات، ولا تحميل assets، ولا اعتماد GPU. الإشارات إلى SVG في مسارات أخرى من المستودع، ومنها registry الأيقونات، لا تتحول تلقائيًا إلى هذا العقد.
