# B3 — Exploded view فوق `machine-kit.js`

المشهد الميكانيكي في الاستوديو (`machine-kit`) كان يُبنى ويُفتح (cutaway) ويلوّن الأجزاء النشطة،
لكنه لا يفكّكها. B3 تضيف **حركة فكّ وتجميع** على نفس النموذج: كل جزء يتحرّك deterministically
بعيدًا عن مركز النموذج ثم يعود إلى **نفس** الإحداثيات بالضبط، من غير صورة أو mesh جديد.

> **الحالة (2026-11-12):** منفّذة في P وK/R (بايتًا ببايت) + معاينة ستة إطارات + 18 اختبارًا.
> **لا** تدّعي: تسميات/أسهم قائمة الأجزاء (BOM)، ولا كاميرا، ولا رندر فيديو حقيقي في هذه البيئة.

## 1. العقد

كتلة `explode` اختيارية داخل الـmachine spec، وكلها داخل نافذة زمن المشهد نفسه:

```json
{
  "id": "nvme-exploded",
  "start": 3.0,
  "end": 8.0,
  "explode": {
    "amount": 0.8,      // 0..1 — أقصى مسافة فكّ
    "start": 5.0,       // داخل [spec.start, spec.end]
    "end": 7.6,
    "hold": 0.34,       // نسبة من النافذة تبقى مفتوحة (0..0.9)
    "spread": 130,      // وحدات عالم Model (0..240)، الافتراضي 110
    "focus": "pcb"      // optional: الجزء/الـtag الذي يبقى ثابتًا
  }
}
```

المراجع: `medo-motion/motion/examples/exploded-nvme.json`.

الرفض (في المحركين بنفس النص): `amount` خارج 0..1 · `start/end` غير منتهيين أو `end ≤ start` ·
النافذة خارج زمن المشهد · `hold` خارج 0..0.9 · `spread` خارج 0..240 · `focus` لا يطابق أي tag.

## 2. الجدول الزمني

```
travel = (end - start) × (1 - hold) / 2
opening : start            → start + travel      easeOutCubic
hold    : start + travel   → end - travel        مفتوح بالكامل
closing : end - travel     → end                 easeInOutCubic
```

`explodeProgressAt(spec, time)` يرجّع `{amount, phase, open}`، و`amount = 0` **بالضبط** عند `start`
وعند `end` — لا «قريب من الصفر». لذلك الإطار الأول والأخير مطابقان للمشهد غير المفكَّك بايتًا.

## 3. الهندسة (قبل الإسقاط)

الفكّ يحدث في العالم ثلاثي الأبعاد قبل `isoProjectPoint`، وليس على الشاشة:

- **الاتجاه:** من مركز النموذج إلى مركز الجزء في المستوى `x,y`، مُطبَّعًا. الجزء الواقع في المركز
  بالضبط يأخذ اتجاهًا من تجزئة (FNV-1a) اسمه — نفس الاتجاه في كل تشغيل.
- **المسافة:** `amount × spread × (0.82 + 0.36 × hash(id))` — تنويع حتمي يمنع تراكب الأجزاء
  المتطابقة الاتجاه.
- **الرفع (z):** `amount × spread × (LAYER_LIFT[layer] × 0.55 + 0.9 × rank)`، حيث
  `LAYER_LIFT = {back:0, mid:0.32, front:0.92, overlay:0.8}` و`rank` ترتيب الجزء في النموذج —
  فيتوزّع الشريحة على شكل مروحة رأسية بدل تكدّسها.
- **`focus`:** الجزء المطابق لـtag يبقى في مكانه (الأرضية/الـPCB عادة).
- كل الإزاحات تُقرَّب بـ`round4`، فالمقارنة بين المحركات تبقى حرفية.

## 4. الأنواع المدعومة

| primitives | كيف تُزاح |
|---|---|
| `slab`, `slab_stack`, `ticks` | `x,y,z` (الطبقات والشرائح ترث إزاحة أصلها) |
| `wire` | كل نقاط `points` |
| `coil`, `cylinder`, `ring` | `x,y,z` (النقاط تُولَّد منها) |
| `poly3d` | كل رؤوس `faces3d` |

الهوية والترتيب محفوظان: `parts[i].id` لا يتغيّر ولا يُعاد ترتيب المصفوفة؛ الترتيب البصري يعيد
ترتيب `ops` لأن `depth` تغيّر — وهذا هو المطلوب، والترتيب يعود كما كان عند `amount = 0`.

## 5. المُفسِّر والواجهة

```js
import { buildMachineScene, explodeProgressAt, explodeMachineModel } from './machine-kit.js';

const g = buildMachineScene(spec, 6.2);   // g.explode = {amount: 0.8, phase: 'hold', open: 1}
```

- `buildMachineScene` نفسها تقرأ `spec.explode` — لا API جديد للمشهد، ولا خيار إجباري.
- المشهد الناتج يحمل `explode` في الـgraph، فالتصدير/الـQA يقدر يتحقّق من الطور.
- لا تغيير في `machineStateAt` (حالة الخطوات/الـmotion مستقلة عن الفكّ).

## 6. القياسات (المُتحقَّق منها في الاختبارات)

## 7. المعاينة

```bash
node tools/machine_explode_preview.mjs medo-motion/motion/examples/exploded-nvme.json out/explode.html
```

ستة إطارات SVG من نفس `buildMachineScene` + `drawMachineGeometry` عبر مُسجِّل Canvas2D بسيط
(تحويلات، مضلعات، خطوط، دوائر، dash) — بلا `Math.random` ولا وقت حائط، والمخرج ثابت بايتًا.

## 8. حدود معلنة

- لا تسميات أجزاء (BOM) ولا أسهم توصل الجزء باسمه — دي طبقة وصفية تحتاج نصًا معتمدًا.
- لا فكّ لكل مجموعة على حدة (stagger بين الأجزاء): كل الأجزاء تتحرك بنفس المنحنى.
- `focus` يقارن `tag` فقط، وليس `id` — لأن الـtags هي لغة المشهد.
- لا حركة كاميرا مصاحبة؛ الكاميرا مسؤولية B5.
- لا يغيّر `machine-kit.py` أي شيء في الرندر: P ترسم نفس الشكل بعد الفكّ لأنها تبني نفس الـops.
