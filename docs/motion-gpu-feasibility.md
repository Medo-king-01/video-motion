# المرحلة السابعة: جدوى Three.js وvgpu قبل الاعتماد

**تاريخ مراجعة المرحلة السابعة: 2026-11-03. قرارها كان الدراسة والفحص فقط.** لاحقًا أضيف نموذج K/R اختياري محدود واعتماد اختبار اختياري؛ [حالة المرحلتين الثامنة والتاسعة](motion-three.md). لا يوجد adapter شامل أو اعتماد مفروض على المحركات العادية. لا نغيّر VO أو مدة الفيلم أو العربية أو البوابات أو المحركات، ولا نضيف واجهة تأليف. `vgpu` هنا مكتبة WebGPU من Vercel، وليس ضمان وجود GPU افتراضي أو تسريع.

## ما فُحص وما لم يُفحص

`tools/gpu_preflight.mjs` يستخدم Playwright/Chromium الموجودين في toolkit المحرك K، ويخدم صفحة اختبار محلية على loopback ويحجب طلبات الصفحة إلى origins أخرى. لا يستورد Three أو vgpu أو Motion، ولا يحاول تنزيل حزم أو تغيير flags للمتصفح:

```bash
export PATH="$PWD/.venv/bin:$PWD/tools/bin:$PATH"
eval "$(node tools/chromium.mjs --env)"
mkdir -p cache/gpu-review
node tools/gpu_preflight.mjs --out cache/gpu-review/preflight.json
node tools/gpu_preflight.mjs --require webgl2    # يطبع JSON
node tools/gpu_preflight.mjs --require both      # exit 1 إذا فشل أي شرط
```

`--out` يكتب ملفًا جديدًا فقط ولا ينشئ مجلده ولا يستبدل ملفًا أو symlink موجودًا. دون `--out` يطبع JSON؛ دون `--require` الإتاحة غير مشروطة، أما `webgl2` أو `webgpu` أو `both` فتجعل عدم اجتياز الفحص المطلوب exit 1. شرط `webgpu` يعني compute smoke فقط، **وليس إثبات قدرة vgpu أو GPU فعلي**. أعِد الفحص على جهاز/عامل الرندر الفعلي وبإعداداته، وليس من متصفح آخر أو sandbox آخر.

- WebGL2: shader صغير يرسم 3 أزمنة ويقرأ RGBA؛ يتحقق من لون معلوم وقيم بداية/نهاية ويقارن الإطارات عند seek عكسي في نفس السياق. لا يفحص Three.js أو مشهدًا أو كفاءة تسريع أو تطابقًا بين الأجهزة.
- WebGPU: يطلب adapter/device ويشغل compute shader يكتب 42، ويتحقق من readback وvalidation؛ لا يختبر رندر canvas أو shaderات الإنتاج أو vgpu. يحد الانتظار بـ15 ثانية، ويغلق المتصفح بعدها.
- `softwareIndicator: detected` يعني ظهور اسم معروف لتنفيذ برمجي؛ `unknown` **ليس** دليلًا على hardware. `adapterFallback` إن توفر لا يثبت وحده وجود/غياب GPU فعلي. لا يسجل التقرير أسماء/معرّفات العتاد الخام؛ معايير كشف البرمجيات ناقصة عمدًا.
- غياب API/adapter حالة `unavailable`؛ أخطاء الإعداد/الفحص `fail`؛ التأخير `timeout`، وليس أي منها نجاحًا. هذه أداة تشخيص محلية، لا تغيير تلقائي في renderer أو مسارات FFmpeg ولا GPU profiler أو شهادة أمنية.

**نتيجة البيئة المختبرة:** Chromium 138.0.7204.0: WebGL2 اجتاز الاختبار المصغر مع مؤشر renderer برمجي، و3/3 أعيدت مطابقتها في نفس السياق؛ WebGPU متاح كواجهة لكن طلب adapter أعاد null. `--require both` أعاد 1 و`--require webgl2` أعاد 0. هذه النتيجة لا تعمم على الأجهزة الأخرى، ولا تبرر ادعاء GPU أو اختبار vgpu؛ تقرير الجلسة في `cache/motion-phase7-proof/preflight.json` (كاش محلي).

## خيار معماري لاحق — لم يُنفذ

| المسار | افتراض مقترح فقط | اختبارات إلزامية قبل القبول |
|---|---|---|
| K | canvas WebGL منفصل مملوك للمشهد، ثم تركيب صورته في 2D عند نفس الزمن المحلي؛ إنشاء الموارد مرة وتنظيف geometry/material/texture/renderer بنطاق المشهد | اختبار Three الفعلي بعد مراجعة الاعتماد، alpha/color/readback، سياق مفقود، فشل init/cleanup، قراءة الإطار بعد الرسم، seek متكرر وعكسي، وQA النص/الوجه |
| R | `useCurrentFrame` يحدد القيم صراحة لكل إطار مع تهيئة وcleanup مملوكين للمكوّن | اختبار على Chromium الخاص بـRemotion ومع تعدد العمال والتقاطه؛ إثبات توقيت/عربية/لون، وإعادة فتح جديدة ومقارنة الإطارات، وليس الاعتماد على probe K |
| P | يبقى مسار Python الحالي؛ أي صور مساعدة يجب أن تكون مؤلَّفة ومولَّدة محليًا ومربوطة بعدد إطارات ونسخة وسياق صريحين | لا browser/GPU مضمر داخل P، عدم إعادة استخدام أصول من وضع/إصدار آخر، فحص هندسة وشفافية وVO |
| Hybrid | المقاطع الحالية متتابعة، وليس composition متعدد الطبقات | كل segment يجتاز عقوده منفردًا ثم عدد الإطارات والمدة والصوت النهائي؛ لا يُفترض دمج طبقات المحركات |
| vgpu/WebGPU | مؤجل حتى توجد بيئة قابلة لإعادة الإنتاج مع adapter مناسب | رسم WebGPU فعلي، device-loss/readback، إدارة الموارد، deterministic frame sampling، نتائج أجهزة/سواقات مختلفة، ثم فحص مكتبة مثبتة ومقفلة |

يجب أن تُحسب transforms/uniforms من الزمن المحلي أو سجل مؤلَّف بلا timers أو live inputs، وأن يبقى ظهور الحقائق تحت مرساة الـVO. تجارب البرامج البحتة لا تثبت أن حسابات floating point أو البكسلات متطابقة عبر GPU/متصفحات. توقيت الرندر/الترميز يجب قياسه على الحمل الفعلي بدل الافتراض أن GPU أسرع.

## القرار التالي

بعد هذه الدراسة أضيف دعم K محدود في المرحلة الثامنة وR في التاسعة، فأصبحت 39 **partial**؛ 40 ما زالت **planned** ولا يوجد دعم vgpu. 43 أصبحت **excluded** بقرار المستخدم: لا Motion+ أو مكوّنات مدفوعة أو شراء. افحص رخص وأمن كل اعتماد مجاني قبل استخدامه أو إعادة توزيعه. لا تُثبّت أي حزمة لمجرد نجاح WebGL2 البرمجي.
