# وزن المستودع (N4)

المراجعة الثانية لقت **152MB من الأصول الثنائية** وراء `.git` بحجم **112MB**، وأكبر مشتبه فيه كان
`assets/poses/source`. الشرط الحقيقي اللي كان ناقص مش LFS — كان **حاجة تلاحظ الزيادة**.

## الوضع المقاس

```bash
python3 tools/repo_weight.py            # تقرير
python3 tools/repo_weight.py --check    # بوابة CI
python3 tools/repo_weight.py --update   # تسجيل خط أساس جديد
```

| الفئة | الوزن | عدد الملفات |
|---|---|---|
| خطوط (`.ttf/.otf/.woff2`) | 81.7 MB | 314 |
| صور (`.png/.jpg/.webp`) | 64.4 MB | 100 |
| نص/كود | 9.2 MB | 1,427 |
| صوت (`.mp3/.wav`) | 6.2 MB | 6 |
| بيانات (`.json/.csv`) | 3.7 MB | 52 |
| **الإجمالي** | **165.2 MB** | **1,899** |

أثقل الملفات: `Merriweather[opsz,wdth,wght].ttf` و`Merriweather-Italic[...]` بـ4.4MB لكل واحد،
و`assets/techniques.json` بـ2.7MB (نص JSON داخل `data`)، ‏`assets/poses/source` بـ35.6MB/49 ملفًا،
و`docs/audition` بـ6.3MB (ستة MP3 للمقارنة السمعية).

## قرار LFS بالأرقام (بدل الرأي)

قِسنا المحتوى **التاريخي** كله، مش الشجرة الحالية بس:

| مقياس | الرقم |
|---|---|
| المحتوى الفريد في كل التاريخ (blobs) | **166.5 MB** في 1,947 كائنًا |
| منه ثنائي (خطوط/صور/صوت) | **152.3 MB = 91.5%** |
| `.git` بعد الضغط | 111.5 MiB (pack) |
| عدد الكومتات | 17 |
| نصوص/كود في التاريخ | 14.2 MB (8.5%) |
| خطوط | 81.7 MB في **314** blob |
| صور | 63.9 MB في **98** blob |
| صوت (`docs/audition`) | 6.2 MB في 6 |

**الاستنتاج الحاسم:** ‏314 blob خط لـ314 ملفًا، و98 blob صورة لـ100 ملفًا — يعني التاريخ **مفيهوش
نسخ متكررة** من الأصول الثنائية تقريبًا. وLFS بيدقّق الـdedupe على مستوى الـblob: بيحرّك نفس
البايتات لمخزن تاني بدل ما يوفّرها. النتيجة العملية:

| الخيار | `.git` | اللي أي حد بيحمّله فعليًا | التكلفة |
|---|---|---|---|
| **زي ما هو** | 112MB | 112MB (+170MB شجرة عمل كاملة) | صفر |
| Git LFS | ~8MB | ~8MB + **~152MB** كائنات LFS عند الـcheckout | إعادة كتابة **كل SHA** + `git-lfs` على كل جهاز وCI، وتاريخ الـLFS على GitHub |
| استبعاد `poses/source` نهائيًا (`filter-repo`) | ~76MB | نفس التحسين | **ضياع الأصل** اللي بيعيد بناء القصّات (`make poses`) — قرار مالك |
| `clone --filter=blob:none --sparse` | 0.26MB من الرسم + كائنات عند الطلب | **كود فقط في ~1MB**؛ الأصول عند الطلب | مافيش rewrite، مافيش اعتمادية |

فالتوصية موثّقة: **مافيش ترحيل LFS دلوقتي** — لأنه ما بيوفّرش بايتات لأي حد بيرندر، وبيكلّف
إعادة كتابة كاملة. اللي بيستاهل يتوثّق هو الاستنساخ النحيف للعمل على الكود:

```bash
git clone --filter=blob:none --sparse <url> video-motion && cd video-motion
git sparse-checkout set tools tests docs medo-motion   # بلا أصول؛ ضِف assets/ لما تحتاجها
```

ولو القرار اتغيّر يومًا (تاريخ 17 كومتًا يعني إن الثمن دلوقتي أرخص ما يكون)، فالوصفة تحت.

## القرار التاريخي (لسه ساري): مافيش Git LFS — وده مكتوب في `.gitattributes`

إضافة فلتر LFS بتغيّر **كل استنساخ وكل مهمة CI**، وبتطلب وجود `git-lfs` عند كل من يفتح المستودع؛
وفي مستودع بلا تعاون خارجي واسع، الوزن الثابت (165MB) أرخص من الاعتمادية المضافة. في المقابل
**نقل تاريخ** (`git filter-repo` + إعادة كتابة كل الـSHAs) قرار مالك مش إصلاح — لأنه بيكسر كل
نسخة موجودة عند أي حد.

## اللي اتعمل بدلًا من كده: سقّاطة (ratchet)

`tools/repo_weight.py --check` بيفرض قاعدتين:

1. **سقف نمو**: الإجمالي المتتبَّع مابيزيدش عن خط الأساس بأكتر من **2MB**. إضافات صغيرة عادية؛
   مجلد أصول جديد بـ30MB بصمت = فشل.
2. **الملفات الثقيلة بالإسم**: أي ملف متتبَّع ≥ **3MB** لازم يكون مذكورًا في
   `docs/repo-weight-baseline.json`. الملف الثقيل الجديد بيتطلب `--update` صريح، والأمر بيطبع
   الفرق، فالقراءة في الـdiff تفضل ممكنة.

خط الأساس محفوظ في `docs/repo-weight-baseline.json`، فكل تغيير في الوزن بيظهر جنب الكود اللي
سبّبه. والفشل بيقول أرقام (`+3.00 MB`، `5.2 MB`) واسم الملف، مش "المستودع كبير".

## الوزن غير المتتبَّع (N11): مشكلة أول تشغيل، مش مشكلة مستودع

`git ls-files` مش بيشوف الحاجات دي، وكلها مستثناة في `.gitignore` — لكنها بتحدد تجربة أول تشغيل:

| المسار | الحجم هنا | مين بيجيبه |
|---|---|---|
| `tools/toolkit/node_modules/` | 85MB | `npm ci --prefix tools/toolkit` (شبكة، مرة واحدة) |
| `.venv/` | 648MB | `bash tools/setup.sh` (pip من `tools/requirements.txt`) |
| `.git/` | 114MB | تاريخ المشروع نفسه |
| مشروع R (`projects/<slug>/node_modules`) | ~400MB | `npm ci` داخل المشروع |

- **الأول تنزيل محتاج شبكة**؛ بعدها `npm ci --prefer-offline` وpip cache بيخلّوا الإعادة أسرع
  بكتير، وبايثون مايحاولش يلمس Python النظام (PEP 668).
- **مانضيفش كاش داخل Git** — ده هيعيد بالظبط المشكلة اللي بنقيسها فوق. الكاش مكانه npm/pip cache
  على الجهاز أو صورة CI.
- أي ملف *جديد* محتاج يتتبَّع في Git بيعدّي من سقّاطة `--check` (نمو ≤2MB + الملفات ≥3MB بالإسم)،
  فالحاجات اللي فوق ماتأثرش على القاعدة لأنها مش متتبَّعة.

## لو القرار اتغيّر لـLFS

الخطوات (مرة واحدة، بقرار مالك وبنافذة تنسيق مع أي نسخة شغّالة):

```bash
git lfs install
git lfs track "assets/fonts/**/*.ttf" "assets/poses/**/*.png"
git add .gitattributes
git lfs migrate import --include="assets/fonts/**,assets/poses/**" --everything
```

وتحديث تعليق `.gitattributes` اللي بيقول «مافيش LFS» في نفس الكومِت، وإلا هيفضل المستودع بيوصف
نفسه غلط.

## الحدود

- الأداة بتقيس **المتتبَّع في Git بس** — مش `.git` نفسه (الـ112MB تاريخ، مش ملفات).
- مابتقررش *إيه* اللي يستاهل يفضل: 4.4MB لخط Merriweather قرار تصميم مش تكرار.
- `--update` مسموح في أي وقت، وهو مقصود: المشكلة كانت **الصمت**، مش التغيير.
