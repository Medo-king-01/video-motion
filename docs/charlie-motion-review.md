## اللي يستحق النقل كمفهوم

### ١. الكارت نفسه يصبح مساحة شرح — تنفيذ أصلي K/R

بدل crossfade بين سطحين، نحافظ على ID واحد ونتحرك بين مستطيلين بوحدة easing الأصلية،
ونرسم shell واحدًا وlabel واحدًا. المحتوى التفصيلي لا يُستدعى قبل استقرار المساحة و`contentAt`.
لا تمديد لحروف العربي، لا نسخة ثانية من العنوان، ولا timer أو reset أثناء الـVO.

- النموذج المشترك: `lib/shared-element.js` في K وR، بنسختين متطابقتين ومختبَرتين.
- K: `drawSharedPanel` في `lib/shared-panel.js`.
- R: `SharedPanel.tsx`؛ label/children يحافظان على نص موجّه بخط اختاره الوكيل.
- ده تنفيذ اختياري لـ`pd-app-window-builds` الموجود في المكتبة، مش حركة مفروضة أو تعديل لدَّرْو الحركات.
  مكتبتنا تفضل 59 حركة، وP يحتفظ بوصفته الحالية؛ **لم نضف adapter جديدًا لـP**.
- المعاينة توضيحية وليست ادعاءً عن واجهة منتج حقيقي. السطح فاتح بألوان ميدو، من غير glass/glow أو شعار.

مثال spec بتوقيت **محلي للمشهد**؛ الأرقام هنا توضيحية فقط، والإنتاج يتبع حدود الـVO المقاسة:

```js
const spec = {
  id: 'detail', start: 0, arrive: 0.8, contentAt: 0.9, end: 1.8,
  from: {x: 620, y: 300, w: 360, h: 140, r: 28},
  to:   {x: 100, y: 500, w: 880, h: 640, r: 28},
};
```

يجب `0 <= start < arrive <= contentAt < end`؛ المستطيلات finite وموجبة والـradius مناسب.
من `arrive` للنهاية تظل الهندسة مطابقة للهدف **بالضبط**. لا طول مستهدف ولا return-to-start.
النموذج يثبت الهندسة والهوية، **لا يثبت أمان الكادر تلقائيًا**: اختر مستطيلات من مناطق الهوية وشغّل QA.

```js
// K: الـcallbacks بإحداثيات الكادر المطلقة، وتُستدعى مرة واحدة لكل إطار نشط.
drawSharedPanel(ctx, spec, localSeconds, {
  drawLabel(ctx, state) { /* drawDirectedText: header, ID ثابت، لا حقيقة قبل مرساتها */ },
  drawContent(ctx, state) { /* drawDirectedText: تفاصيل، بعد contentsReady فقط */ },
});
```

```tsx
// R: داخل سطح relative-positioned؛ CSS بإحداثيات محلية، مش state.box.x/y المطلقة.
<SharedPanel spec={spec} time={localSeconds}
  label={state => /* DirectedText للعنوان */ null}>
  {state => /* DirectedText للتفاصيل */ null}
</SharedPanel>
```

في R مرّر `style={{fontSize: chosenSize}}` مع `size={chosenSize}` لـDirectedText؛
`size` وحده يضبط offsets الحركة، وليس حجم CSS الموروث. جميع النصوص ما زالت تحت عقد
`text-direction.json` و`copy.json`. الـhelper لا ينشئ copy أو أرقامًا أو خطًا افتراضيًا.
`contentAt` يؤخر الرسم حتى توجد مساحة، لكنه **ليس** بديلًا لمرساة الكلام؛ اجعله عند/بعد الكلمة
المقاسة المسموح بكشف المعلومة معها، واربطها بخطة `visual-direction.json`.
لا تعمل clip لإخفاء فشل التخطيط؛ راجع أحجام النص وهوامش المساحة عند البداية والمنتصف والاستقرار.

### ٢. إعادة seek عكسيًا — دليل بكسلات مش مجرد وعد بالحتمية

```bash
node tools/layout_audit.mjs --project projects/my-reel \
  --out projects/my-reel/cache/layout-replay-v1 --replay
```

إضافة اختيارية لفحص K الحالي، بدون renderer/dependency جديد:

1. يرسم الإطارات المختارة بالترتيب الأمامي ويسجل SHA-256 لبكسلات RGBA الفعلية بكامل حجم الكانفس،
   مع snapshot النصوص/المناطق المحمية. لا نستخدم thumbnail رمادي يخفي اختلاف اللون.
2. يعيد نفس الإطارات بترتيب عكسي ويقارن الصورة والـsnapshot.
3. `R01`: البكسلات تغيرت عند نفس الزمن؛ `R02`: بيانات التخطيط تغيرت. أي منهما يجعل الفحص FAIL،
   مع الإطار/الثانية وصور لحالات الإعادة المخالفة. يلتقط حتى 6 صور replay بجانب حد صور التصادمات.
4. التقرير يفصل `replay.status` عن layout، ويسجل عدد الإطارات ونسخة Chromium والـscale.
   بدون `--replay` الحالة `not-requested`، فلا تدّع أن فحص الحتمية اتعمل.

سياق الكانفس في audit يُنشأ بـ`willReadFrequently` لتجنّب تبديل مسار raster أثناء قراءات البكسلات؛
الـrender العادي لا يتغير. تفعيل الفحص يزيد وقت الرسم والقراءة ويحتفظ بالـhashes فقط، مش كل صور الإطارات.
`--every 6` يصلح لتجربة سريعة لكنه يختبر **العينات فقط**؛ الإنتاج الافتراضي كل إطار عند 30fps.

**حدود صريحة:** النجاح ملاحظة في نفس صفحة/متصفح/تشغيل، وليس برهانًا رياضيًا أو ضمان تطابق
بين المتصفحات أو مع تصدير GPU/الملف المضغوط، ولا fresh-load test. لا يكشف اعتمادًا على ساعة حقيقية
إذا لم تتغير قيمتها خلال القياس، ولا يثبت صحة الأرقام أو القراءة أو اكتمال الأصول منطقيًا.
الرجوع العكسي **مش فحص seamless-loop**؛ آخر إطار مشفّر عند `(N-1)/fps` مختلف عن زمن نهاية المقطع
`N/fps`. مفيش مقارنة مفروضة بين نهاية الفيلم وبدايته لأن الفيلم تحت VO مش loop.

| reference-to-motion | فصل الحركة عن الشكل كتحليل مفيد؛ STYLE الحالي يأخذ خصائص الحركة العامة فقط، وهوية ميدو تتغلب دائمًا على ألوان/خطوط المرجع. |

| loop-cover | قياس الحركة/الحد الفاصل مهم لو طلب المستخدم cover مستقلًا. لا نفرض return أو GIF على فيلم الـVO، ولا نتعامل مع أرقام seam الرمادية كمعيار جودة عام. |
| milestone-reveal | seed ثابت، font-ready، وقراءة البكسلات ألهموا تقوية QA. لا particle numbers افتراضية، ولا اختصار رقم أو تقديم هدف على أنه نتيجة. |
| apple-launch-film | استمرار الشيء عبر التحول هو الفكرة القابلة للتكييف؛ لا notch أو Apple palette/system font/تعليمات تثبيت apple-design. |

| newsletter-promo | hook ثم دليل ثم خلاصة نمط تحريري عند ملاءمته، لا قالب/اسم سلسلة/عدد مشتركين افتراضي. |
| model-showdown | مقارنة بنفس الإعدادات مفيدة لاختبار تقني منفصل، مش مكونًا للاستوديو. لا استدعاء نماذج/حسابات/شعارات أو وصول لخدمات خارجية. |
| title-sequence-3d | الموجود من space3d يكفي الآن؛ لا Three.js/bloom/rain setup جديد ولا مقدمة تستهلك مدة التعليق أو صوتًا مولدًا بدل VO الأصلي. |
| vox-explainer | كل shot يشرح نقطة، ومصادر للحقائق، وعدم تحويل التشابه لسببية. لا نسخ Vox/torn-paper/yellow palette أو 24fps stepped timing بدل 30fps الأصلي. |
| reel-export | ffprobe وفحص ملف التسليم مبادئ موجودة. لا نستبدل safe zones الهوية بأرقام منصة غير مثبتة، ولا نضيف AAC صامتًا ليبدو الفيديو تسليمًا مكتملًا. |

- الحفاظ على النسخة السابقة وإصلاح مشكلة واحدة بملاحظة وإطار محدد أسلوب مراجعة مفيد؛ لا ندّعي تعديلًا

## إعادة إنتاج الأدلة

```bash
export PATH="$PWD/.venv/bin:$PWD/tools/bin:$PATH"
python3 tools/visual_verify.py --out cache/continuity-proof --shared --replay --remotion
python3 -m pytest tests/test_motion_quality.py -q
bash tools/ci.sh
python3 tools/selftest.py --remotion --hybrid
```

الأمر ينشئ مجلدًا **جديدًا** فقط: معاينات K/R، تقرير shared لـ54 إطارًا، إعادة فحص بيانات لـ180 إطارًا،
وحالة R01 مصطنعة للتأكد من رفض الحالة المعتمدة على تاريخ الرسم. ينتج مقطع K تجريبيًا صامتًا مدته 1.8s
باسم `motion/shared-shell-silent-test.mp4`؛ **مش** فيديو تسليم أو مزامنة مع تسجيل حقيقي.
توقيت الإنتاج وكل كشف معلومة يظل مشتقًا من VO المشروع. اللون/الخط/الصوت/Hybrid كما كانوا،
والـZod mismatch warning وdrawtext الاختياري في البيئة مشاكل معلومة سابقة، ليست اعتماديات جديدة من هذه الحزمة.
