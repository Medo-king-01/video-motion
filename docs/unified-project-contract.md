# عقد المشروع والـTimeline الموحّد — المرحلة صفر

**الحالة: مواصفة تصميم مع نواة أولية محدودة للوسائط والتحرير والحفظ وخطة graph غير قابلة للتنفيذ.** يوجد الآن
[`unified-project.schema.json`](../medo-motion/schema/unified-project.schema.json) وفاحص
`tools/unified_project_check.py` لمجموعة وسائط أولية وcompiler تجريبي موضح أدناه؛ لا يوجد محرر
أو adapter من P/K/R/Hybrid يقرأ الـgraph أو يرندره. توجد معاينة مرجعية محدودة لإطار واحد كما
هو موضح أدناه، مع تصدير مرجعي صامت شديد المحدودية؛ باقي النماذج أدناه تصميم مستقبلي وليس دعمًا منفذًا. المستودع الحالي يظل شغالًا
بعقوده الحالية إلى أن تُنفّذ الهجرة وتُختبر. الأولوية تأسيس العقد قبل الواجهة ومكتبة حركات جديدة.

لتجربة الفاحص: `python3 tools/unified_project_check.py tests/fixtures/unified_project/basic.json`.
يرجع 0 للصالح، 1 للبيانات غير الصالحة أو غير المدعومة، و2 للملف غير المقروء أو JSON غير سليم.
يفحص الشكل والعلاقات فقط، ولا يفتح الوسائط ولا يختبر وجودها أو hash أو symlinks أو قابلية الرندر.
النسخة الأولية تقبل مقاطع `media` فقط؛ الإصدار 1.0 يشترط فراغ `effects` و`keyframes`،
والإصدار التجريبي 1.1 يدعم تخزين وتقييم المؤثرات المحدودة الموضحة أدناه فقط. مسارات النص والرسوم
يمكن أن تكون فارغة فقط. يرفض الإصدارات والحقول المجهولة حفاظًا على البيانات، ولا يكتب المشروع
ولا يدّعي فتحه للتحرير. الوعود اللاحقة بالقراءة فقط وround-trip والهجرة لم تُنفذ بعد.

توجد دوال Python نقية محدودة في `tools/unified_project_edit.py`: `split_clip(project, clip_id, at, new_id)`،
`trim_clip(project, clip_id, start, end)`، و`move_clip(project, clip_id, track_id, start)`.
كلها ترجع نسخة جديدة أو ترفض العملية دون تعديل الأصل، وتتأكد من صلاحية المدخل والنتيجة. Trim داخلي
فقط، والصور تحتفظ بـ`sourceIn=0`. يرفض split المقاطع ذات المؤثرات، ويرفض trim تغيير حدود
مقطع متحرك، حتى يُنفّذ تحويل المعرفات والمنحنيات دون فقد؛ المقاطع المرتبطة غير مدعومة. `ripple_delete(project, start, end, track_ids)` يحذف المقاطع داخل المجال بالكامل ويزحزح
اللاحقة في المسارات المختارة فقط؛ يرفض أي مقطع يعبر حد الحذف ويترك مدة المشروع صريحة بلا تغيير.
`History` في `tools/unified_project_history.py` يوفر undo/redo بذاكرة محدودة داخل العملية؛ لا يحفظ
التاريخ بين الجلسات. `tools/unified_project_time.py` يحسب عدد الإطارات والعينات ويقدم snap حتميًا
للـplayhead وحدود المقاطع وشبكة الإطارات. دي مكتبات مستقلة وليست واجهة تحرير أو محرك رندر.

تضيف `tools/unified_project_author.py` إنشاء مشروع 1.0 فارغ من profile محدد، وإضافة المسارات
وترتيبها وتفعيلها وإضافة مقطع وسائط وحذفه وضبط مدة المشروع وإلغاء تسجيل أصل غير مستخدم. لا تزيد
إضافة المقطع المدة تلقائيًا، وإزالة مسار غير فارغ أو أصل لا يزال مرجعه مستخدمًا تُرفض. إلغاء تسجيل
الأصل لا يحذف الملف من القرص. هذه عمليات نقية قابلة للاستخدام مع `History`؛ الفاحص يرفض التداخل
والأنواع غير المتوافقة ومراجع الأصول غير الموجودة، والنتائج نسخ منفصلة. ليست واجهة مرئية.

`tools/unified_project_store.py` يوفر `load(path)` و`save(path, project, expected_revision)`:
حفظ ذري بملف مؤقت في نفس المجلد، وقفل تعاوني وhash لكشف تعارض كتّاب يستخدمون نفس الآلية؛
الإنشاء فقط عند `expected_revision=None`، وأي إصدار/حقل غير مدعوم يمنع الكتابة فوق الملف حتى لو
توفر hash له. القفل المتروك بعد انقطاع العملية يحتاج مراجعة وإزالة يدوية؛ لا يوجد autosave أو
استرداد تلقائي أو نسخة احتياطية أو تنسيق مع برامج تتجاهل القفل. لا ضمان حماية أمام تغييرات منافسة
من برنامج لا يلتزم بالقفل، أو ضد مجلد غير موثوق، ولا ضمان اكتمال الكتابة بعد انقطاع الكهرباء
(لم نختبر fsync للمجلد). يُرفض ملف المشروع إن كان symlink، لكن لا يُفحص احتواء ملفات الوسائط هنا.

فحص الوسائط اختياري عبر `python3 tools/unified_project_media.py /path/to/project.json`، ومع `--probe`
يطلب `ffprobe` محليًا بعد نجاح فحص hash؛ `--ffprobe` يحدد مساره عند الحاجة. ينتج JSON لكل أصل
بحالة `ok`, `missing`, `changed`, `error` أو `probe_error`، ويرجع 0 لو كلها سليمة، 1 لو أصل فشل،
و2 لو المشروع غير صالح أو غير مقروء. يتحقق من مكونات المسار ويرفض symlinks؛ يعرض metadata الخام
من ffprobe دون اختيار stream أو إثبات أن مدته تطابق المشروع. لا يستورد، ولا ينشئ proxy أو waveform،
ولا يعدّل الملفات. `import_asset` في المكتبة ينسخ ملفًا محليًا موثوقًا إلى مسار جديد داخل المشروع،
ويحسب SHA-256 ويرجع نسخة مشروع تشمل الأصل؛ مجلد الوجهة يجب أن يكون موجودًا ولا يقبل الكتابة فوق
ملف موجود. يعتمد النشر على hard link؛ لو نظام الملفات لا يدعمه تفشل العملية بدل الكتابة فوق الملف.
المدة تُعطى يدويًا بوحدة ticks للوسائط الزمنية، ولا تُستنتج أو تُطابق تلقائيًا مع metadata. حفظ
المشروع منفصل عن الاستيراد، لذا انقطاع أو فشل الحفظ قد يترك ملفًا منسوخًا غير مسجل؛ لا يوجد cleanup
تلقائي أو معاملة ذرية تجمعهما. لا thumbnails أو proxies أو waveforms بعد.
لا يشكل هذا حماية ضد تغيير خبيث متزامن للملفات؛ شغّل ffprobe فقط على وسائط ومجلد موثوقين، فهو
 decoder خارجي وليس sandbox. لا يثبت الفحص أن الأصل سيبقى نفسه حتى الرندر لاحقًا.
مراجعة المصادر الخارجية وحدود الاستفادة في [editor-source-review.md](editor-source-review.md).

### مؤثرات 1.1 التجريبية

يسمح 1.1 بـ`opacity` على مسار فيديو و`gain` على مسار صوت، نسخة المؤثر `version: 1`؛
كل مؤثر له ID فريد بالمشروع، `enabled` و`params: {"value": عدد صحيح}` بوحدات 1/10000.
الشفافية بين 0 و10000، والكسب الخطي بين 0 و20000 (حتى 2×، وليس ديسيبل).
قائمة المؤثرات مرتبة لكن لا يوجد تنفيذ لتركيبها أو تعريف لطريقة المزج بعد.
`keyframes` يحتوي منحنى واحدًا على الأكثر لكل مؤثر في المقطع، بالشكل
`{"effectId":"fx", "property":"value", "points":[{"t":0,"value":0,"interpolation":"linear"}]}`.
النقاط غير فارغة، أوقاتها المحلية صحيحة ومتزايدة تمامًا حتى مدة المقطع شاملًا، وقيمها ضمن
نطاق المؤثر. الدالة `effect_value` ترجع كسرًا دقيقًا: خارج أول وآخر نقطة تثبت قيمة الطرف؛
داخل المجال تحدد `interpolation` للنقطة اللاحقة الانتقال إليها: `linear` أو `hold` لقيمة
النقطة السابقة حتى الوصول للاحقة. interpolation للنقطة الأولى لا يؤثر. دون منحنى تستخدم القيمة
الثابتة، والمؤثر المعطل يرجع `None`. مدة المقطع نفسها حد تقييم صالح لكنه خارج فترة التشغيل
نصف المفتوحة. التحريك يُخزّن ويُقيّم فقط: **لا معاينة أو رندر لهذه المؤثرات بعد**، ولا يجوز
اعتبار أي محرك حالي داعمًا لها. لا توجد هجرة تلقائية بين 1.0 و1.1؛ الدالة
`enable_effects_contract` في `tools/unified_project_effect_edit.py` تتيح ترقية صريحة إلى 1.1.
توفر المكتبة نفسها إضافة مؤثر واستبداله مع الحفاظ على ID، وإضافة منحنى أو استبداله وحذفه، وحذف
المؤثر فقط بعد حذف منحناه صراحة. كل تغيير يتحقق من المشروع والنتيجة ويمكن استخدامه مع History،
ولا يفعّل المعاينة أو التصدير للمؤثر.

## القرارات والحدود

منصة تحرير واحدة، وطرق العمل Free Edit وScript to Video وTalking Head وMontage وPodcast وExplainer
وProduct Review وMotion Design تنشئ **نفس المشروع القابل للتحرير**، مش محركات أو صيغ نهائية منفصلة.
الطبقات المقترحة: Editor → Project/Timeline → Media + Composition → Render Graph Compiler →
P/K/R/Hybrid → Export/QA. الواجهة لا تنفذ الرندر بنفسها. هوية ميدو الواحدة تظل المرجع؛ لا brand
profiles متعددة. لا AI في قلب المحرك أو اتخاذ قرارات التحرير. تحديد مصادر أو خدمات إضافية مستقبلًا
لا يجعلها جزءًا من النواة.

ده اتجاه جديد يتجاوز قرار استبعاد واجهة التأليف في [motion-rollout.md](motion-rollout.md) للمنصة
المستقبلية، **ولا يغير** حدود ما نُفّذ في خطة Motion السابقة. كذلك مشاريع الريلز الحالية تبقى خاضعة
لقواعد VO و30fps والهوية في [length.md](length.md) و[AGENTS.md](../AGENTS.md)، لحد تنفيذ مسار
منصة جديد صريح واختباره؛ المشروع العام الجديد يستطيع أن يكون صامتًا أو بلا VO. لا نغيّر سلوك الأدوات
الحالية بالوثيقة وحدها.

## 1. Project Schema

المقترح ملف `project.json` في مجلد مشروع يختاره المستخدم، خارج Git عند الاحتفاظ به. البيانات
المؤلفة هي المصدر الوحيد للحقيقة؛ الـproxies والـwaveforms والمعاينات والرندر كاش قابل لإعادة البناء.
مثال توضيحي مصغّر، لا يقرأه أي محرك حالي:

```json
{
  "schemaVersion": "1.0",
  "id": "project-1",
  "name": "Example",
  "profile": {"width": 1080, "height": 1920, "fps": {"num": 30, "den": 1}, "sampleRate": 48000},
  "timebase": 240000,
  "duration": 480000,
  "seed": 42,
  "assets": [{"id": "a1", "kind": "video", "uri": "media/shot.mp4", "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef", "duration": 720000}],
  "tracks": [{"id": "v1", "kind": "video", "enabled": true, "clips": [{"id": "c1", "kind": "media", "assetId": "a1", "start": 0, "duration": 480000, "sourceIn": 0, "effects": [], "keyframes": []}]}]
}
```

- حقول المثال إلزامية، بما فيها المصفوفات الفارغة؛ `duration` للمشروع طول مؤلف صريح، موجب أو صفر
  للمشروع الفارغ، ويحتوي كل المقاطع. الأسماء اختيار المستخدم ولا تظهر في الصورة تلقائيًا.
- `schemaVersion` major.minor؛ major غير معروف يُرفض دون حفظ فوق الأصل. minor أحدث أو حقول غير
  معروفة تُحفظ دون فقد لكن يُفتح المشروع للقراءة فقط ما لم يضمن التنفيذ round-trip آمنًا؛ لا رندر
  إذا كانت الدلالات المجهولة قد تؤثر على النتيجة. الهجرات إصدارًا بإصدار، حتمية وغير مدمّرة، مع
  نسخة احتياطية وتقرير؛ لا تعديل صامت لملف قديم.
- IDs نصوص مستقرة وفريدة داخل المشروع، والمراجع تتحقق قبل الرندر. ترتيب المصفوفات معنوي؛ الحفظ
  لا يعيد توليد IDs. المسارات محفوظة بصيغة `/` النسبية إلى جذر المشروع؛ لا `..` أو مسارات مطلقة
  أو روابط رمزية تهرب من الجذر. الوسائط الخارجية تُستورد أو تُربط مستقبلاً بآلية سماح صريحة، لا
  تُنفّذ URI كأمر أو URL. المشروع بيانات غير موثوقة ولا يحمّل كودًا منه تلقائيًا.
- الحفظ الذري بملف مؤقت في نفس المجلد ثم استبدال، مع كشف تعارض النسخة عند تعدد الجلسات؛ autosave
  واستعادة بعد الانقطاع لا يطمسان نسخة صالحة. العمليات غير المحفوظة/تاريخ undo ليست جزءًا من الرندر.

## 2. Timeline Model

**الوقت:** كل أزمنة المشروع والأصل والـkeyframes أعداد صحيحة في ticks؛ `timebase` عدد ticks لكل
ثانية، في المثال 240000. `fps` كسر موجب ومختزل؛ يشترط `timebase * fps.den` قابلية القسمة على
`fps.num` و`timebase` القسمة على `sampleRate`، فتقع حدود الإطارات والعينات على ticks صحيحة.
العينة البصرية للإطار `n` عند `n * timebase * fps.den / fps.num`؛ العينات الصوتية عند
`n * timebase / sampleRate`. الفترات كلها نصف مفتوحة `[start, start + duration)`؛ لا تداخل عند
حد قطع متجاور. عند الاستيراد تُحوّل الطوابع الزمنية النسبية بدقة كسرية ثم تُقرّب لأقرب tick،
والتعادل للأعلى، ويُسجّل أي فقد دقة. قيم الأعداد المحفوظة لا تتجاوز `2^53-1`؛ الحسابات الوسيطة
التي قد تتجاوز هذا الحد تحتاج أعدادًا صحيحة دقيقة مثل `BigInt` في JavaScript، لا أعدادًا عائمة.
الفاحص الأولي يشترط تمثيل الأعداد الصحيحة كـJSON integer، لا `1.0`، حتى لو اعتبرها فاحص
JSON Schema عددًا صحيحًا رياضيًا. عند التصدير يُختار عدد إطارات `ceil(duration / frameTicks)`،
وعدد عينات صوت `ceil(duration * sampleRate / timebase)`، مع ملء الجزء الأخير عند الحاجة؛ مدة
الحاوية قد تزيد أقل من إطار/عينة. هذا **مقترح للنواة الجديدة فقط** وليس تفسيرًا جديدًا لتقريب
`beats.json` الحالي. لا يُغيّر FPS المشروع مواقع الـticks تلقائيًا.

- `tracks` مرتبة من أسفل الصورة إلى أعلاها؛ صوت المسارات المفعلة يُمزج بترتيب ثابت. الأنواع
  الأولية: `video`, `audio`, `text`, `graphics`؛ تعريف الـcaption والانتقالات ضمن إصدار لاحق من
  العقد، ولا يجوز الادعاء بأنها قابلة للرندر هنا. `enabled=false` يخفي/يكتم المسار دون حذف محتواه.
- `clips` لها ID وkind و`start` و`duration` موجبة. `media` تشير إلى أصل و`sourceIn` غير سالب؛
  v1 يقترح سرعة 1 فقط، فالمجال المصدر هو `[sourceIn, sourceIn + duration)` ولا يتجاوز مدة الأصل.
  الصور الثابتة ليس لها نهاية مصدر، ولا يسمح `media` إلا بأصل متوافق مع نوع المسار. الفجوات شفافة
  بصريًا وصامتة صوتيًا؛ التداخل داخل نفس المسار مرفوض في v1، والتراكب يتم بمسارات مختلفة.
- النص والرسوم نوعان مطلوبان للـMVP، لكن محتواهما وقواعد تشكيلهما واتجاههما وخطوطهما تحتاج schema
  تفصيليًا واختبارات قبل التنفيذ؛ لا تُستخدم أمثلة مبهمة كترخيص لرندر نص ناقص. قواعد العربي والهوية
  الحالية إلزامية في مسار الريلز.
- `split` عند tick داخل المقطع: قطعتان بنفس الأصل؛ الثانية تبدأ بمصدر `sourceIn + offset`.
  `trim` يحافظ على علاقة المصدر بالـtimeline ولا يقرأ خارج المصدر؛ تحريك مقطع بين مسارات يتطلب
  توافق النوع. `ripple delete` يحذف المجال المحدد ويحرك المقاطع اللاحقة في المسارات المختارة؛ إذا
  تقاطع الحد مع مقطع آخر يلزم تقسيم صريح أو رفض العملية. لا تعديل صامت لمسارات غير مختارة.
  كل عملية مع تغييراتها على keyframes قابلة للتراجع ذريًا. تفاصيل حواف المؤثرات والصوت والربط بين
  المقاطع تُحدد وتُختبر قبل تفعيل هذه العمليات في الواجهة.
- Snap قرار تحرير فقط: أهداف واضحة (حدود مقاطع، playhead، شبكة إطارات)، أولوية ثابتة ومسافة
  معلنة؛ يحفظ الناتج ticks لا حالة المؤشر. Undo/redo سلسلة أوامر قابلة للعكس، تُفرغ redo عند تعديل
  جديد؛ لا تدخل في التجميع أو تحدد النتيجة النهائية.

## 3. Media Asset Model

الأصل `id`, `kind` (`video`, `audio`, `image`), `uri`, `sha256` ومعلومات المدة عند الوسائط
الزمنية. فحص hash قبل الرندر يمنع تبديل ملف بصمت؛ الأصل الناقص أو المختلف يُعرض offline ولا يمنع
فتح المشروع، لكنه يمنع الرندر المتأثر حتى relink صريح والتحقق من المحتوى. URI موقع وليس هوية.

تُخزن خصائص ffprobe مثل streams، معدل الإطارات الأصلي، وقت البداية، rotation، القنوات وأبعاد
الصورة كمعلومات مستخرجة بإصدار أداة؛ ليست بديلًا عن الملف. اختيار stream يجب أن يكون صريحًا
لملف متعدد المسارات قبل الرندر. تحويل VFR إلى عينات المشروع يعتمد timestamps الفعلية وليس افتراض
fps ثابت؛ أصول تالفة أو timestamps غير قابلة للتفسير تُرفض بتقرير. الـproxy/thumbnail/waveform
اختيارية ولا تغيّر محتوى الأصل؛ المفتاح يشمل hash الأصل، stream، إعدادات وإصدارات أدوات التوليد.
المعاينة بالـproxy معلّمة وقد تختلف جودتها؛ الرندر النهائي يستخدم الأصل المتحقق. لا نضع ملفات
المستخدم أو الكاش أو المخرجات في Git.

## 4. Effect & Keyframe Model

المقطع يملك قائمة `effects` مرتبة؛ كل effect له `id`, `type`, `version`, `enabled`, `params`.
تطبيق المؤثرات بصريًا وصوتيًا من أول القائمة لآخرها؛ لا تُنفّذ effect مجهولة ولا تُحذف عند الفتح.
الـregistry يحدد نوع المعامل ووحدته ومداه وقيمة default الصريحة ودلالته وإصدار التنفيذ ودعم كل
backend. لا كود أو تعبيرات عشوائية في المشروع. تمثيل الـtransitions بين مقطعين سيُحدد منفصلًا؛
لا تُفترض مساواتها بمؤثر على مقطع واحد.

`keyframes` قائمة curves لكل property مسموح بها من الـregistry، بأزمنة ticks **محلية للمقطع**،
وقيم typed مرتبة تصاعديًا وأزمنة فريدة. قبل أول مفتاح وبعد آخره تثبت القيمة الطرفية؛ interpolation
`hold` أو `linear` أو easing معروف بإصدار مثبت، ويحدد المفتاح الواصل منحنى الفترة السابقة، توافقًا
مع [motion.md](motion.md). لا interpolation تلقائي للنصوص أو القيم المتباينة النوع. لا curves
مكررة لنفس الخاصية. عند split تُقيّم قيمة الحد وتُضاف كحد للطرفين مع إعادة إزاحة أزمنة القطعة
الثانية؛ الحفاظ الدقيق على منحنيات easing غير الخطية يتطلب تقسيم المنحنى رياضيًا أو رفض العملية،
لا إعادة تقريب صامتة. `trim` يحتفظ بالقيمة والمنحنى عند الحد بالطريقة نفسها. لا فرض أن كل easing
حالي قابل للتحويل بلا فقد قبل إثباته.

## 5. Render Backend Contract

الـcompiler المقترح دالة على snapshot مشروع متحقق + manifest للأصول والاعتماديات + طلب رندر
صريح، وتُخرج graph مرتبًا أو diagnostics بأكواد ومسارات عناصر؛ لا side effects أثناء التحليل.
الـgraph يحمل إصداره، نطاق الإطارات/العينات، ترتيب التركيب والمزج، إعدادات profile وseed، hashes
الأصول والإصدارات المطلوبة. لا تعتمد النتيجة على وقت النظام أو ترتيب العمال أو حالة المعاينة.

كل adapter مستقبلي يعلن معرفه وإصداره ونسخة graph وقدراته، ويتحقق قبل التنفيذ، ثم يرندر النطاق
المطلوب بإحداثيات زمن مطلق ويدير الموارد والتنظيف، ويرجع تشخيصًا ومخرجات محددة. عدم دعم أي جزء
مرئي أو مسموع = فشل صريح قبل التصدير، بلا إسقاط أو استبدال تلقائي؛ يجوز fallback فقط باختيار
المستخدم الصريح وتقرير الاختلاف، ولا يعد رندرًا مطابقًا. Hybrid منسّق/مركّب وليس محركًا مستقلًا
ذا قدرات مجموع المحركات تلقائيًا.

**الحتمية:** لنفس المشروع والأصول والـseed والـgraph وإصدارات المحركات والخطوط والمكتبات وأدوات
الترميز والبيئة المضبوطة يجب تكرار الإطارات وعينات الصوت؛ ملفات الحاوية قد تختلف metadata الخاصة
بها ما لم تُثبّت أيضًا. لا نعد بتطابق بكسلي بين P/K/R أو منصات/إصدارات مختلفة: rasterization
والخطوط وGPU وencoder قد تختلف. تُختبر المساواة داخل بيئة مثبتة، والتكافؤ بين المحركات بمقاييس
وتسامحات معلنة لكل ميزة، أو يُرفض التنفيذ. المعاينة النهائية تستخدم الـgraph نفسه؛ معاينة proxy أو
خفض الدقة/fps مُعلّمة تقريبية. الـseed وحده لا يكفي لضمان حتمية الاعتماديات.

### خطة graph التجريبية المنفذة

`tools/unified_render_graph.py` يتحقق من المشروع ثم ينشئ خطة `graphVersion: 0.1` و
`compilerVersion: 0.1` غير قابلة للتنفيذ (`executable: false`). تحتوي نسخة مستقلة كاملة من المشروع،
وترتيب المسارات والمقاطع كما هو، وحالة المسارات، ومراجع الأصول ومسارات التشخيص. `clock` يتضمن
خطوة الإطار والعينة وعدديهما بتقريب للأعلى؛ لكل مقطع نطاق ticks نصف مفتوح ونطاق مؤشرات عينات
`[ceil(start/step), ceil(end/step))`، حيث step خطوة الإطار للفيديو والعينة للصوت. هذه مؤشرات
عينات تقع أوقاتها داخل المقطع، لا إثبات لإمكان فك الوسائط أو التركيب. المسارات المعطلة ومحتواها
تبقى في الخطة؛ لم يُنفذ بعد اختيار streams أو المزج أو اللون أو التعامل مع VFR والحواف والتعبئة.

لتجربتها: `python3 tools/unified_render_graph.py tests/fixtures/unified_project/basic.json`.
الخطة لا تفتح الأصول ولا تتحقق من الملفات أو hashes ولا تنفذ الرندر. المكتبة تعطي digest حتميًا
لـJSON مرتّب المفاتيح وفق ترميز Python لهذه النسخة؛ ليس معيار canonical JSON عبر اللغات ولا
بصمة دليل على صلاحية الوسائط أو حتمية الصورة. `preflight(project, backend)` وخيار CLI مثل
`--backend P` يرفضان جميع P/K/R/Hybrid برمز R01 حتى يتوفر adapter حقيقي؛ CLI يرجع 1 عند
الرفض أو خطأ الإدخال، و0 عند إنتاج الخطة فقط. لا يستنتج preflight دعمًا من قدرة المسارات القديمة.
تلك الخطة مرحلة وسيطة، وليست بعد عقد backend نهائيًا أو graph تنفيذ عام أو فحص قدرات تفصيلي.

### معاينة مرجعية لإطار واحد

`render_frame(project, root, frame_index)` في `tools/unified_reference_preview.py` يترجم المشروع
عبر الخطة السابقة ويرجع قاموسًا مع `pixels` بايتات RGBA8 متتالية من أعلى لأسفل، وقياسات الإطار
ووقته المطلق. هذا إثبات تنفيذي ضيق داخل Python، لا واجهة عرض ولا ملف فيديو ولا adapter لأحد
المحركات الأربعة. يسمح بمسار فيديو مفعّل واحد كحد أقصى يحتوي صورًا ثابتة فقط؛ الفجوات بكسلات
سوداء شفافة، والصورة معتمة، وتُنسخ قيم RGB دون إدارة ألوان أو تغيير حجم. صورة المصدر يجب أن
تطابق أبعاد المشروع وبصيغة PPM ثنائية 8-bit مع رأس حرفي
`P6\n<width> <height>\n255\n` وبيانات RGB بلا بيانات إضافية. الحد الأقصى لإجمالي البكسلات هو 4096×4096.

يرفض أي صوت مفعّل يحتوي مقاطع، أي فيديو متحرك أو أكثر من مسار فيديو مفعّل، وأي مؤثر أو
keyframe على مسار مفعّل حتى لو كان المؤثر معطّلًا. المسارات المعطلة لا تظهر ولا تُفتح أصولها.
يفحص وجود وسلامة مسارات وأبعاد وبصمات كل الصور المشار إليها في المسارات المفعّلة، حتى لو لم تظهر
في الإطار المطلوب؛ أصول المكتبة غير المستخدمة لا تُفتح. تُحسب البصمة من البايتات نفسها التي تُرسم.
يرجع `PreviewError` مع `code` و`path` للأخطاء الخاصة بالمعاينة، أو خطأ صلاحية المشروع من compiler.
المجلد والوسائط يجب أن يكونا موثوقين: رفض symlink لا يضمن الأمان أمام تغيير المسارات بالتزامن.
لا دعم للصوت أو ملفات الصور الشائعة أو التأثيرات أو التركيب متعدد الطبقات أو الرندر النهائي.

### تصدير مرجعي محدود

`python3 tools/unified_reference_export.py project.json output.mkv --ffmpeg /path/to/ffmpeg`
يستخدم مسار الإطار المرجعي نفسه، ويكتب فيديو صامت FFV1 في Matroska عبر FFmpeg محلي موثوق يدعم
الترميز وBGRA؛ الفجوات تحتفظ بقناة alpha في هذا المسار. هذا ليس تصدير MP4 عامًا أو دعمًا لأحد
P/K/R/Hybrid. تُرفض كل الحالات التي ترفضها معاينة الإطار، حتى لو كانت خارج الإطار الحالي؛ لا يُحذف
الصوت أو المؤثرات المفعّلة بصمت. يلزم وجود المشروع والصور والمجلدات مسبقًا، وهي موثوقة؛ لا يجري
تثبيت FFmpeg تلقائيًا. عدد الإطارات يقرّب للأعلى حسب عقد الوقت، وقد تُكمّل الحاوية آخر فترة إطار؛
توقيت الحاوية يعتمد دقة Matroska ونسخة FFmpeg، ولم يُثبت تطابق timestamps لكل معدلات الإطار.

يُنتج جميع الإطارات في الذاكرة قبل بدء FFmpeg: سقف البيانات الخام 64 MiB و10000 إطار، مع ذروة
ذاكرة فعلية أعلى من حجم البيانات الخام. يُرفض المشروع الفارغ. الملف المؤقت في مجلد الوجهة ويُنشر
برابط صلب دون استبدال ملف موجود؛ نظام الملفات الذي لا يدعم hard links يفشل بدل الكتابة فوق الملف.
يُنظّف الملف المؤقت في حالات الفشل المعتادة لكن الانقطاع القسري قد يتركه. لا توجد استعادة بعد
الانقطاع أو ضمان ضد تغيير خبيث متزامن للمجلد أو ضمان نسخ متطابقة بايتًا بين إصدارات FFmpeg.
اختبار تكامل اختياري يفك FFV1 ويتحقق من RGB وalpha وعدد الإطارات؛ يُستخدم FFmpeg في PATH أو
`TEST_FFMPEG` للاختبار، ويُتخطى عند غيابه. لم يُختبر المسار على Windows أصليًا بعد.

## 6. Editor Capabilities وحالة المحركات

التحرير، المعاينة، الرندر والتصدير قدرات منفصلة. يقترح manifest بإصدار backend لكل ميزة/إصدارها،
وقيم `supported`, `conditional`, `unsupported`, `unknown` مع الشروط والدليل. الواجهة تحفظ
البيانات حتى لو لا يمكن رندرها؛ تظهر سبب الرفض والعنصر والمسار والبدائل، ولا تفعل زر تصدير مضلل.
لا تتحول `conditional` إلى دعم إلا بعد تحقق شروطها للـgraph المطلوب. أي extension مجهول يُحتفظ به
كما سبق؛ لا يجوز تعديله أو تصديره كأنه مدعوم.

| القدرة الحالية ذات الصلة | P | K | R | Hybrid |
|---|---|---|---|---|
| قراءة المشروع الموحد أو تنفيذ graph المقترح | غير منفذ | غير منفذ | غير منفذ | غير منفذ |
| الحركة الحالية | `motion.py` | `motion.js` | نسخة JS مشتركة | يستخدم المحرك المختار؛ ليس دعمًا مستقلًا لكل خاصية |
| انتقالات الكتالوج الحالية | مدعومة ضمن مسارها | مدعومة ضمن مسارها | قطع مشاهد فقط حاليًا | حسب قيود الخطة والمحرك؛ ليس انتقالًا عامًا |
| طبقات شفافة | ليس overlay في Hybrid | overlay شفاف بشروط | ليس overlay في Hybrid | أساس واحد وحتى 4 overlays من K مع قيود المشاهد والماسك |
| draft الحالي 15fps | موجود | موجود | مرفوض | موجود ضمن قيود الخطة |
| تحرير عام متعدد المسارات/وسائط خام | غير مثبت | غير مثبت | غير مثبت | غير مثبت |

تفاصيل الأدلة في [motion.md](motion.md)، [transitions.md](transitions.md)،
[hybrid.md](hybrid.md)، و[preview.md](preview.md). القدرات أعلاه تخص المسارات الحالية، **وليست**
إقرارًا بقدرة أي منها على قراءة العقد الجديد. ملفات الخطط والتوقيت الحالية، بما فيها
`plan/beats.json` و`plan/hybrid.json` وP `scenes.py` وK `src/data.js`، ليست نموذجًا موحدًا؛
Hybrid يختار مقاطع المحركات ولا يعيد كتابة مشاهدها.

## التوافق والهجرة

- لا نستبدل أو نعدّل ملفات المشاريع الحالية تلقائيًا. importer مستقبلي غير هدّام ينتج مشروعًا
  جديدًا وتقريرًا لكل عنصر: محوّل دون فقد، محفوظ كمرجع غير قابل للتحرير، أو غير قابل للتحويل.
  ملفات `scenes.py` وJS/TS قد تتضمن كودًا اعتباطيًا؛ لا يمكن افتراض تحويلها إلى clips قابلة للتحرير
  أو تنفيذها بأمان كبيانات. النسخ الأصلية تبقى مصدر الحقيقة للمسار القديم.
- التصدير العكسي للمسار القديم غير مضمون؛ عند غياب mapping كامل يفشل بصراحة. `beats` وتوقيت VO
  يحافظان على قواعدهما وأدوات فحصهما؛ لا نختزل توقيت الكلمات أو الخطوط أو بيانات المراجعة بصمت.
- تبدأ profiles المستقبلية بـ30fps كافتراضي للريل القديم؛ 60fps والمقاسات الأخرى أهداف لاحقة،
  وdraft 15 الحالي مسار معاينة مختلف، لا دليل على دعم profiles عامة. Windows الأصلي هدف تصميمي
  يحتاج اختبارًا حقيقيًا؛ [development.md](development.md) يوثق البيئة الحالية بما فيها WSL،
  وليس وعدًا بأن كل أدوات اليوم تعمل native Windows.

## معايير إكمال المرحلة صفر قبل البرمجة اللاحقة

1. تحويل الصيغة إلى JSON Schema بإصدارات واضحة وvalidator دلالي للمراجع والحدود والتوافق؛ fixtures
   صالحة وخاطئة واختبارات حفظ/قراءة وهجرة دون فقد، بما فيها إصدارات غير معروفة.
2. اختبارات حساب ticks والحدود نصف المفتوحة والتحويل الكسري وVFR ومدة التصدير، وحدود split/trim
   وripple وundo/redo مع audio/keyframes؛ رفض الحالات التي لا يمكن الحفاظ على معناها.
3. مواصفة تفصيلية للنص والعربي والخطوط والصوت والانتقالات والـeffects وأنواع المسارات قبل تفعيلها؛
   واختبارات capability لكل backend مع فشل صريح وdiagnostics، لا مصفوفة دعم متفائلة.
4. إثبات عمودي صغير: مشروع media بسيط ← تحقق ← graph ← adapter واحد ← معاينة/رندر ← QA، مع
   اختبار التكرار داخل بيئة مثبتة؛ ثم توسيع البقية بعد إثبات كل mapping. لا يتطلب هذا إعادة كتابة
   المسارات القديمة أو إعلان دعم المحركات الأربعة دفعة واحدة.
5. تصميم عمليات حفظ آمنة وrelink وكاش واختبار مسارات Windows/Linux وملفات ناقصة وتغيّر hash؛
   مراجعة تراخيص أي اعتماد أو كود أو أصل قبل الاستيراد. لا نسخ لكود Hojas أو أصوله بافتراض إباحته.

**قرارات تفصيلية مفتوحة:** تمثيل النص والكابشن والـtransitions والـaudio automation، واجهة
manifest والـgraph الفعلية، آلية اختيار streams، وسياسة حفظ النسخ والتعارض متعدد الجلسات. لا
تُملأ هذه الفجوات بادعاء وجود دعم؛ تُحسم مع أول schema/اختبارات تنفيذية.
