# الترجمة (B6) — SRT وVTT من نفس نص الشاشة

**الحالة:** منفّذ 2026-11-12 · **الأداة:** `tools/subtitles.py` · **الاختبارات:** `tests/test_subtitles.py`

المصدر هو `plan/copy.json` — نفس الملف الذي يقرأه الرندر ليكتب الكابشن على الشاشة. لا قائمة نصوص
ثانية تُصان باليد، فلا ت drifting بين ما يُقال وما يُكتب. البناء **حتمي**: نفس الملف يعطي نفس البايتات.

---

## 1. الشكل

`copy[]` في `copy.json` يحمل لكل مدخل: `id` · `text` · `start` · `end` (ثوانٍ). الأداة:

1. تنظّف النص (مسافات، أسطر، محارف تحكم) وتتحقق من الأرقام.
2. ترتّب حسب `start` ثم `end` ثم `id` — الترتيب في الملف لا يهم.
3. تعالج التداخل: **رفض** افتراضيًا (`S02`)، أو دمج صريح (`--on-overlap merge`) يضمّ النص ويمدّ النهاية.
4. تفرض مسافة `gap = 0.04s` بين أي cue والتالي.
5. تفرض **أقل مدة قراءة 0.6s**: تمدّ النهاية إن كان هناك مكان، وإلا ترفض (`S03`) بدل أن تنتج سطرًا يومض.
6. تلفّ النص على سطرين بحد أقصى **42 محرفًا** للسطر؛ ما لا يتّسع يُرفض (`S04`) ولا يُقصّ.

الناتج cue list واحدة، منها يُكتب SRT وVTT و`subtitles.json` (بيانات التوقيت + بصمة المصدر).

## 2. الأكواد

| الكود | معناه |
|---|---|
| `S01` | شكل: نسخة 1، حقول معروفة، `copy[]` غير فارغة، حزمة cue كاملة |
| `S02` | ترتيب/هوية: تداخل، `id` مكرّر، ترتيب غير تصاعدي |
| `S03` | توقيت: `0 ≤ start < end`، أقل من `minDuration`، أو لا مكان قبل الـcue التالي |
| `S04` | نص: فارغ، كلمة أطول من المسموح، أو أكثر من السطرين |
| `S05` | `totals` لا تطابق الـcues (عدد/مدة/أول/آخر) |
| `S06` | إعدادات غير صالحة (`minDuration ≤ 0`، `gap < 0`، `maxChars < 8`، `maxLines` خارج 1..3) |

## 3. الصيغتان

```srt
1
00:00:00,000 --> 00:00:01,500
النهاردة
```

```vtt
WEBVTT

00:00:00.000 --> 00:00:01.500
النهاردة
```

- SRT: فاصل فاصلة عشرية `,`، ترقيم تسلسلي `1..n`.
- VTT: ترويسة `WEBVTT` وحدها، فاصلة عشرية `.`، بلا ترقيم تسلسلي.
- المحارف `<` `>` `&` تُهرَّب في VTT فقط، لأنها تُقرأ كوسم هناك.
- التوقيت `HH:MM:SS.mmm` بعد تقريب للمللي ثانية؛ الساعات تتجاوز 99 بلا مشكلة.
- النص العربي يُكتب كما هو (لا تشكيل، لا RTL/LTR marks، لا تغيير أرقام).

## 4. البيانات (`subtitles.json`)

```json
{"version": 1,
 "source": {"name": "copy.json", "sha256": "…"},
 "settings": {"minDuration": 0.6, "maxChars": 42, "maxLines": 2, "gap": 0.04, "onOverlap": "reject"},
 "cues": [{"id": "…", "start": 0.0, "end": 1.5, "lines": ["النهاردة"]}],
 "totals": {"cues": 11, "duration": 23.2, "first": 0.0, "last": 23.2}}
```

`check` يفحص الملف وحده: الشكل، الترتيب، التوقيت، النص، و`totals`. هكذا يمكن مراجعة الترجمة قبل
تسليمها، وكشف أي تعديل يدوي عليها.

```bash
python3 tools/subtitles.py build plan/copy.json --srt out/ar.srt --vtt out/ar.vtt --manifest out/subtitles.json
python3 tools/subtitles.py check out/subtitles.json
```

خيارات `build`: `--min 0.6` · `--max-chars 42` · `--max-lines 2` · `--gap 0.04` · `--on-overlap reject|merge`.
الخروج: `0` تمام · `1` نص/cues مرفوضة · `2` ملف غير مقروء.

## 6. ما لا تدّعيه B6

- **مفيش ترجمة آلية ولا ASR**: المدخل نص مكتوب مسبقًا؛ الصوت له مساره (`word-timings.json`) خارج هذا الملف.
- **مفيش تصدير فيديو مع ترجمة محروقة**: هذا ملف نصي جانبي؛ الحرق يحتاج رندرًا حقيقيًا.
- **مفيش دعم حروف CJK/RTL مختلط بذكاء**: النص العربي يُكتب بترتيبه المنطقي كما هو، والعرض مسؤولية المشغّل.
- **مفيش "تحسين" صياغة**: الأداة تنظّف وتلفّ فقط، والكلمات لا تتغيّر.

## 7. الخطوة التالية

قرارات المالك حُسمت: EDL للتسليم ([`edl.md`](edl.md)) · 60fps تجريبي بالطلب · هوية واحدة (ميدو).
المتبقي تنفيذًا: ربط ملفات الترجمة بمحرّكات الرندر وحرقها عند الطلب.
