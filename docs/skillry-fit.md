# Skillry: fit for the Medo Motion studio

**Reviewed:** 2026-11-01 · **Scope:** public Skillry pages/listings only. This is a relevance and workflow review, not a source-code, ZIP, or licence audit of the marketplace Skills.

## Recommendation

Use Skillry as an **idea and workflow-structure reference**, not as a renderer, runtime dependency, or source of ready-to-install Skills. The public catalogue packages agent workflows with a target output, required inputs, runtime dependencies, and sometimes paid providers; the site advertises support for a broad range of agents. That compatibility packaging adds little for this repo because `medo-motion/SKILL.md` is already host-agnostic and delegates to the shared `AGENTS.md` contract. The video listings include HyperFrames examples; some advertise local rendering but still require Node/FFmpeg, and optional image, voice, music, or editing services can incur separate costs.

The studio already has a stronger native fit for Medo's constraints: measured timing from VO, `assets/techniques.json` plus `tools/techniques.py`, project-specific `STYLE.md`, native P/K/R renderers, and the sequential hybrid renderer. It would be wasteful and risky to install another motion library without inspecting its actual package and rights. In particular, the public CreatorMotion description is a HyperFrames-oriented Pro Skill whose effect categories (type, presenter layouts, transitions, evidence/focus, comparisons, process diagrams, cards, and interfaces) substantially overlap our measured techniques. It adds its own palettes, Smiley Sans, image pool, aspect presets, and separate-segment workflow; its stated requirements include HyperFrames CLI, Node 22+, FFmpeg, and a one-time background-removal model download for some presenter effects. It is not a drop-in extension of P/K/R.

**Decision on buying/installing a Skillry Skill: not recommended at this stage.** Revisit only if there is a concrete production need that the Medo toolkit cannot meet and the actual ZIP, source, licence, dependency tree, and any provider costs can be inspected first. Page ratings, download counts, and preview videos are not a substitute for those checks.

## First-party adaptations for Medo

Use these as optional creative recipes—not new render engines and not extra intake requirements:

1. **Evidence-first capability/explainer:** state one verified claim → show one genuine screen/action/output → give its consequence → close on the approved takeaway. If no genuine evidence was supplied, use a clearly illustrative interface and do not present it as a real product capture.
2. **UI/product demo:** choose one action per sentence; show the real state before, the cursor/tap, and the changed result. Existing starting points: `pd-cursor-does-the-demo`, `ui-state-change-on-tap`, `pd-app-window-builds`, and `pd-before-after-hard-swap` in `assets/techniques.json`.
3. **Cross-surface proof:** use only when the product really works on multiple named surfaces. Keep the tested input and output consistent; sequence full-frame P/K/R segments when appropriate. The hybrid renderer does not layer engines simultaneously, and does not make one engine's effects available in another.
4. **Language-launch beat:** verify the supported languages and final translated copy; keep the title/read order legible; apply `reference/arabic-typography.md` to Arabic. Treat another language's line as content requiring review, not an automatic translation side effect.
5. **Social proof:** use only user-supplied or rights-cleared sources, track source/permission in the project's credits, and do not infer endorsement from a public post.

These recipes are illustrations of ways to organize a brief. They do not replace the four-input Medo contract, change the VO-derived duration, insert an approval gate before rendering, or change the locked brand.

## Safe adoption checklist for any external Skill

Before considering installation, inspect the complete Skill payload and record: licence/redistribution terms; scripts and shell commands; exact renderer/tool versions; network access and files it reads/writes; optional/required API keys and paid calls; generated media rights; format/aspect/duration assumptions; and whether its claimed effects run in P, K, R, or only its own runtime. Then prototype only the narrow technique in a throwaway project, translate it to the Medo palette/type/Arabic/VO contract, run visual and automated checks, and document the engine limits. Never copy an entire starter, credentials, proprietary assets, or preview media into this repository.
